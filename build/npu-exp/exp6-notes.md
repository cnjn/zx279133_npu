# exp6：出口计数器对照（续查）

上轮会话最后一次对照：20 个 ping，X=48 有 95 项计数超过空闲增量至少 15；X=0 没有项目达到门槛。这不是“所有计数器都没动”。恢复后 pc 3429 回读为 `0x0018000601000003`，ping 有回复；这不能证明采样期间的状态。

复核 `/tmp/exp6.py` 发现：

- `snap()` 丢弃 sysfs 文件标准输出，仅保留 dmesg；写到 stdout 的统计不会出现在结果里。文件读取错误也被丢弃。采样列表不包含按队列的 `queue_stats` 或 `ssch_port_stats`。
- `ping(20)` 不保存发送结果，且两次串口快照夹在 ARP 刷新和发包之间。没有 en8 发出的 ICMP 帧数，无法区分未入板和板内丢包。
- 三次快照缺失的键被当成 0；一次下降就被当作读清。两者都会污染差值。

下一轮先不改微码：用 X=48 做正对照，同时记录 en8 实际发出的 ICMP 请求数、板上入口包计数，以及目标出口统计的 stdout 和内核日志。只比较三次快照共有且语义已确认的键，保留原始值，匹配空闲和流量窗口时长。能辨认出该批请求后再做 X=0 对照；若入口未见该批请求，不给出口编号赋义。

## 原配置正对照（未写微码）

- `baseline-en8.log`：en8 捕获同一 ICMP id 的 seq 0–19 请求和对应回复，抓包内核丢包 0。板上 eth0 空闲窗口 RX/TX 增量 +21/+3，ping 窗口 +53/+20。Linux RX 混有背景包，不能替代微码前的硬件入口计数。
- `baseline-stats-help.log`：`ssch_port_stats` 是只读节点，结果在 dmesg；`queue_stats` 是只写的查询节点，单纯 cat 不能采样。
- `baseline-ssch-repeat.log`：另一次 20/20 ping 中，SSCH port 4 的 ack/req/deq/enq 四项均为 206 → 206 → 226 → 226（空闲、发包、空闲）。其余端口保持 0。`baseline-ssch.log` 是超时的初次采样，未用于上述差分。
- port 4 是已验证的正常 ping 往返参照，但往返包含请求和回复，不能据此认定它就是 X=48 的直接目的端口。
